# Исправление ложных уведомлений — 12.10.2026

## Причина

`replace_group_lessons()` сравнивал входные пары только с записями того же
`source_type`. При первой обработке файла `changes` предыдущих записей этого
типа ещё нет, хотя базовое расписание `schedule` уже сохранено. Поэтому функция
возвращала `changed=True` даже при полностью одинаковых парах. Обработчик
обновлений добавлял группу в `changed_groups` и отправлял уведомление.

Это воспроизводит описанный случай: базовое расписание ТД-24-9 на 14.10.2026
и первый файл изменений содержат одинаковые пары, но раньше второй файл
считался изменением. Это не ошибка определения факультета по префиксу ТД.

## Что изменено

- Для сравнения загружаются записи обоих источников для конкретной группы и даты.
- Предыдущее актуальное расписание выбирается по тому же правилу, что при показе:
  если есть `changes`, используется весь набор его пар; иначе — базовое расписание.
- Первый файл изменений сравнивается с базовым расписанием. Если пары совпадают,
  `changed=False`, и группа не попадает в рассылку.
- При наличии изменений загрузка базового файла не вызывает уведомление:
  отображаемым источником остаётся `changes`.
- Сохранение не отключено: одинаковый файл изменений всё равно записывается в БД.
  При этом удаляются только прежние записи обрабатываемого типа; базовый файл
  сохраняется отдельно. Значок «С учётом опубликованных изменений» может остаться,
  но сам по себе больше не является причиной уведомления.
- Сравнение по номерам пар сохранено: порядок строк не влияет на результат.

Миграция или очистка БД не требуется. Изменены `app/database/repository.py`
и регрессионные тесты `tests/test_no_false_schedule_changes.py`.

## Проверка

Добавлены тесты:

1. Первый `changes` с теми же парами, что у `schedule`: без изменения.
2. Реальная смена кабинета в `changes`: изменение; повторная загрузка базового
   файла и того же `changes`: без изменения; возврат кабинета: изменение.
3. Удаление пары в первом `changes`: изменение.

Полный запуск `python -m pytest tests -q`: 60 тестов прошли.
Предупреждения openpyxl касаются неподдерживаемых расширений и областей печати
Excel, не падений тестов.

Проверка выполнена локально. Серверная рассылка не запускалась; после пересборки
следует проверить первый идентичный файл изменений и файл с реальной заменой
для одной группы. Исправление касается выбора источника для сравнения; оно не
добавляет новое сравнение звонков, нормализацию текста или изменения парсера.
